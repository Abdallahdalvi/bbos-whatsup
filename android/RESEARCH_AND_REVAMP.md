# Q20 Messenger research and revamp audit

Research date: 2026-11-03. Target: BlackBerry Q20 Android API 18 runtime, existing Nokia4Ever/NovelProfessor single linked WhatsApp session. Implementation changes were prepared in local staging. The owner subsequently deployed 0.9; read-only live diagnostics confirm WhatsApp connected on Chrome 156 with call modules/helpers loaded. The assistant did not modify the live container/authentication or call a real recipient. Successful ringing and duplex audio remain pending.

## Version 0.9 additions

Actual open-source interface code now includes Android Support Library AppCompat 28.0.0, [Google Material Design icon assets](https://github.com/google/material-design-icons), and [PhotoView 2.0.0 source](https://github.com/Baseflow/PhotoView/tree/2.0.0) for image gestures. The API 18 minimum prevents using current Material 3 Android components directly; compatibility widgets provide the Android presentation without raising the runtime requirement. Included notices preserve the upstream licenses and copyrights.

The user's installed browser is Chrome 146, matching Puppeteer 24.38.0. The library also defaults to a Chrome 101 user-agent string; 0.9 disables that stale default or uses the actual selected browser's agent. Neither finding alone proves why live calls failed. Chrome 156.0.8078.80 is listed in [Google's stable Chrome for Testing metadata](https://googlechromelabs.github.io/chrome-for-testing/last-known-good-versions-with-downloads.json), and passed a scratch-profile launch/Web Audio check with the pinned Puppeteer here. The x64 server updater independently validates it on Linux before selecting it, retaining a stopped-profile backup and previous browser config.

Confirmed local fixes include duplicate incoming events rejecting the current call, early call-registration checks, cached preview padding, UI input clipping, audio-source/rate fallbacks, and preserving error details. Authenticated diagnostics are added so the next real call failure can be inspected directly. The call-link module loader follows the upstream [lazy module-loading fix](https://github.com/wwebjs/whatsapp-web.js/pull/201950); the app's primary call action now starts a direct voice call.

| [mautrix-whatsapp](https://github.com/mautrix/whatsapp) | A Matrix bridge built around WhatsApp protocol integration. | A complete Matrix deployment would introduce another server/client layer and still require Q20 client compatibility. Not a small drop-in backend patch. |
| [WA-JS](https://github.com/wppconnect-team/wa-js) | Browser-side WPP API for contacts, messages, groups and media. | Useful comparison for extraction/action designs. Injecting another large wrapper alongside WWebJS may conflict with private browser hooks; no unverified combination shipped. |

Graphics attribution and CC-BY-4.0 license are included. |

Combining separate WhatsApp libraries is not equivalent to merging feature checklists. They own different credential stores, message models, encryption state and runtime hooks. The implementation keeps a single session adapter and introduces explicit structured presentation data. This is an engineering inference from the inspected architectures, not a claim that a migration is impossible.

## Concrete defects addressed in 0.7

1. **Authentication:** plain Node/Docker startup did not load an API token from a file. Both HTTP and WebSocket authentication now use one configuration reader: a nonempty environment value first, otherwise private config adjacent to the server. The personalized patch contains the user-supplied token. Public source/snapshot ZIPs exclude that secret.
2. **Names:** contact filtering incorrectly discarded business and LID records. Removed those exclusions, added additional profile fields and chat.getContact lookup, preserved good names, propagated resolved phone names to LID aliases, and stopped generic conversation rows masking message profile names. Actual names cannot be invented when WhatsApp has neither a saved nor a profile name.
3. **Message fidelity:** non-text messages were flattened into labels. The server and Android database now preserve a whitelist of poll options, captions and CTA actions, with additive schema migrations. Old poll/button rows are repaired from WhatsApp when opened if the linked session still exposes the message.
4. **Polls:** added selectable single/multiple answer UI and a real server vote action, with option validation and error reporting. Empty selection withdraws a vote. Poll creation and live aggregated vote counts are not added in this build.
5. **Business actions:** received supported URL, phone and copy CTAs perform the corresponding device action. Quick replies, list selections, payment/commerce actions and WhatsApp Flows require additional protocol/UI support and remain unsupported. They are not simulated by sending ordinary text.
6. **Emoji:** bundled modern emoji graphics, sequence matching and a basic insert picker. Sending preserves Unicode. The composer itself still uses the device font; supported chat text uses image spans.
7. **Calls:** added MODIFY_AUDIO_SETTINGS, a call wake lock and voice volume controls; guarded call start races; added orphan/incoming timeouts, remote stream disposal and microphone failure detection; bounded uplink latency and enabled WebSocket ping. Incoming prompts and calls still need device tests. Background ringing/answering with a persistent Android service remains unfinished.
8. **Responsiveness:** foreground call checks use a thread pool so they do not queue behind a long history task. Existing cached history still opens immediately.

## Acceptance criteria still required

The code and fixture tests do not establish a fully equivalent WhatsApp client. Required real-account acceptance includes two-way call audio for at least 10 minutes, remote/local hang-up, reject/busy/no-answer, Wi-Fi loss, speaker/earpiece routing and screen-off behavior; saved, unsaved, business and LID contact names; old/new polls in private/group chats; modern emoji sequences; business action samples; and original media transfer on the Q20. These need access to the staged linked session and physical device. No such test was performed here.

Remaining product gaps include background incoming calls/notifications, complete message editing/revoke/reactions/replies UI, poll creation/results, arbitrary business reply/list/Flow actions, communities/status parity and group calling. This release is a substantial integration repair, not a claim of complete official-client parity.
